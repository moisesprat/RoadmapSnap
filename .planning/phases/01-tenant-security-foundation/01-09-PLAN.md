<objective>
Close the one verification gap (CR-01, ROADMAP success criterion 2 / SEC-01): a client abort must never hand a tenant's database client to another request while the aborted handler is still using it. Add WR-01 pool and client error handling in the same file family.

Purpose: today `onRequestAbort` in `packages/api/src/plugins/context.js` (lines 186-192) runs ROLLBACK, releases the client and nulls `request.dbClient`, while the handler keeps querying through the reference it captured. The verifier reproduced an aborted org A request running its trailing query inside org B's transaction, and an aborted write that turned org B's request into a 500. Any authenticated tenant can trigger this at will. The fix stops releasing from the abort hook. Fastify 5.7.4 skips `reply.send` (and therefore `onSend`) when an async handler resolves `undefined` after the socket is gone (`lib/wrap-thenable.js`), and `onResponse` only listens for `finish` and `error` (`lib/reply.js` `setupResponseListeners`). So deleting the release alone would leak the connection on that path, and a small settle guard finalizes those handlers. WR-01 stops a pool or checked-out client `error` event from crashing the process, and makes a saturated pool fail fast.
Output: the fixed `context.js`, the hardened `client.js`, four abort regression tests and two checked-out-client tests in `tenant-tx.test.js`, and a new `db-client.test.js`.
</objective>

## Flagged assumptions

- A disconnected client's transaction now commits or rolls back by status, like a connected one. The old hook tried to roll back on abort, but it only fired when Node set `req.aborted`, which happens only for requests whose body was not fully read, so it was never a consistent rule. Rolling back on every disconnect would need socket inspection on every path. The user can ask for that as a revision. It is reversible.
- The settle guard goes beyond the verifier's "delete the hook" suggestion. Reading Fastify 5.7.4 showed one path where neither onSend nor onResponse runs (a handler resolving `undefined` after an abort). Without the guard, that path leaks a connection.
- The `pg_terminate_backend` test assumes the admin role from DATABASE_URL may signal the app role's backends. That holds for the superuser owner used locally and in CI.
