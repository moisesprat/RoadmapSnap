<objective>
Prove tenant isolation on the real API request path with one end-to-end slice, then move every existing API test onto that path.

Purpose: Today the API connects as a superuser, so RLS is bypassed, a stranger is auto-joined to the seed org, and the tests only pass because of that bypass (RESEARCH F2-F5). This plan makes a signed-JWT request run as `roadmapsnap_app` inside one transaction, with identity and org resolved under FORCE RLS through self-select policies (D-08). It also removes the `X-Test-User-Sub` impersonation path (D-09).
Output: V13 tenant policies, the rewritten tenant-transaction plugin, RS256-pinned local-JWKS auth, shared test helpers, the tracer cross-tenant test, and the existing auth/projects/workspaces tests migrated to signed JWTs.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser/client → API | Untrusted bearer token, `X-Org-Id` header and `?orgId` query cross here |
| API → PostgreSQL | The API acts for one tenant per request; isolation depends on the role, the transaction and the GUCs it sets |
| test tooling → API | The local JWKS is a second trust anchor that must never be live in production |

## Flagged assumptions

These are researcher and planner choices the user can override. None is a one-way door.
- A1: Error code names `NOT_A_MEMBER` and `INVALID_ORG_ID` (HTTP 400 for a malformed id). D-13 fixes only the 403. The rename is cheap now and becomes costly once Phases 4 and 6 route on these codes.
- A2 and A3 (RESEARCH Open Question 1, recommendation followed): `users` RLS and the REVOKE and search_path hardening ship in V13. The user can drop them by asking for a revision; Phase 4 builds on users RLS.
- A4: 30 s idle-in-transaction timeout for the app role.
- A8: The performance of `app_current_*()` in policies was not measured. Switch to the `(SELECT app_current_org_id())` initplan form if large tables show per-row cost.
- RESEARCH Open Question 3 (tokens without email): the planner chose a clean 403 `EMAIL_REQUIRED` with no schema change, over dropping `NOT NULL` on `users.email`. Phase 4 owns the Auth0 Action or `/userinfo` fallback (STATE.md blocker). Real Auth0 access tokens without an email claim cannot sign in until then, as today, but they no longer cause a 500.
- Pitfall 8 (two subjects, one email): answered with 409 `EMAIL_IN_USE` instead of a 500. Account linking is Phase 4.
