## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser/client → API | Untrusted bearer token and arbitrary request headers cross here; only the Authorization header may identify the caller |
| API → browser/client | `/auth/me` responses leave the server and must carry only the fields the SPA needs |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Spoofing | `plugins/auth.js` impersonation header | high | mitigate | The header block is deleted in the same commit as the test move. auth.test.js asserts 401 for a header-only request and that the header is ignored next to a valid token. 01-05's no-bypass guard fails if the literal returns to packages/api/src |
| T-01-39 | Information Disclosure | GET and PATCH /auth/me responses | low | mitigate | Both responses are built field by field (sub, email, name, preferences, role, orgId, orgs), and the raw JWT payload is never spread (grep gate on `...request.user` = 0, RESEARCH Pitfall 6) |
| T-01-SC | Tampering | npm installs | low | accept | No package is added or upgraded. jose is already installed (RESEARCH "Package Legitimacy Audit": none) |
</threat_model>
