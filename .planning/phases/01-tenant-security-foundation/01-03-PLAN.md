<objective>
Make migrations schema-only: a fresh install gets tables, policies and indexes but no sample program data, and existing dev databases are left alone.

Purpose: SEC-05 and D-01..D-04. V7-V12 currently create a seed org, a seed user and hundreds of rows of real program data, and V8 cross-joins every user into the seed org. Output: an exported `migrate()`, a non-overriding `.env` loader, scratch-database test helpers, `seed-fresh.test.js`, and the six edited migration files.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repository → fresh database | Whatever migrations insert lands in every new install, so seed data in migrations is data exposure by default |
| migration runner → existing databases | Edited migration files must not re-run or diverge on databases that already applied them |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-18 | Information Disclosure | V7, V9, V11, V12 real program data | medium | mitigate | Files reduced to comment-only stubs, so HEAD holds no real data. Git history is deliberately not rewritten (D-03; history purge deferred per CONTEXT) |
| T-01-19 | Tampering | editing applied migrations | medium | mitigate | migrate.js tracks by filename, so recorded versions are skipped. The idempotency test and the local `npm run migrate` run prove existing databases are untouched (D-01, D-04) |
| T-01-20 | Elevation of Privilege | V8 cross-join of every user into the seed org | high | mitigate | V8 stubbed. The fresh-install test asserts zero org_members and zero organizations |
| T-01-SC | Tampering | npm installs | low | accept | No package added or upgraded |
</threat_model>
