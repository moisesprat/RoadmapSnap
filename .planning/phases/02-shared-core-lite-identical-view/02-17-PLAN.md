<objective>
Catch Lite-vs-SaaS drift early. A parity-only preview renders the React Lite-area components from the same fixture data Lite uses, routed through the core adapter, and the 02-06 harness compares them with Lite pixel by pixel in the pinned container. This plan also builds the export controls and footers, so the preview covers every region that exists outside the timeline.

Purpose: Waves 6 to 9 are serial. Without this plan the first SaaS-vs-Lite pixel comparison would come in 02-16, and drift in the dashboard or filter-bar models (02-10) or components (02-12) would mean rework under 02-13..02-16. This plan runs in wave 6, in parallel with 02-13, and checks the dashboard, filter bar, export controls and footers. 02-14's tracer then swaps the preview composition for LiteRoadmapView and adds the first full-area check, before 02-15 and 02-16. The preview loads only the shared tokens CSS, so a failure here points at core models, markup or shared CSS, not at page chrome. D-01, D-08, D-10 and D-15 apply unchanged. VIEW-06 (exports, D-12) moves here from 02-12 with its tests intact.
Output: `parity-view.html`, `src/parity/view.tsx`, the Vite `--mode parity` build into `dist-parity`, the `build:parity` script, `build-targets.mjs --saas`, the 4303 static server, `tests/view-vs-lite.spec.ts`, plus `LiteExportControls`, `LiteFooter`, `download.ts` and the Vite build-time constants. 02-16 reuses this infrastructure and adds the real page entry.
</objective>
