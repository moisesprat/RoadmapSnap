# Phase 02 — UI Design Contract

> Visual and interaction contract for Phase 02: Shared Core & Lite-Identical View. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## How to read this contract

This phase has two visual zones. The contract is different for each.

| Zone | What it is | Source of truth | Who may change it |
|------|-----------|-----------------|-------------------|
| **Lite area** | Lite's filter bar, export controls, `#roadmap-export` (dashboard + timeline) and footers | `js/ui/*`, `css/roadmap.css`, `packages/tokens/components.css`. Lite is the oracle (CONTEXT D-10). | Nobody in this phase. SaaS reproduces it; it does not restyle it. Any change to Lite CSS changes both products at once. |
| **SaaS chrome** | The thin header (D-02), the project modals (D-03), notices, loading/error/empty states | This document | This phase |

Anything this document says about the Lite area is a parity rule, not a design choice. The typography, spacing and color tables below declare values for the **SaaS chrome only**. The Lite area keeps its existing token and CSS values verbatim (they predate this phase, use more than 4 type sizes and 4 weights, and must not be normalized, because parity is the Core Value).

Sources used: CONTEXT.md D-01..D-16 (all locked, nothing re-asked), `js/ui/{dashboard,filterBar,exportControls}.js`, `js/app.js`, `css/roadmap.css`, `packages/tokens/{tokens.css,tokens.js,components.css}`, `packages/app/src/{index.css,pages/DashboardPage.tsx,components/layout/*,components/projects/*}`.

## Spacing Scale

Declared values for the **SaaS chrome** (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding inside chips and notices |
| sm | 8px | Gap between header controls, button vertical padding, dialog row gaps |
| md | 16px | Dialog body padding, notice padding, gap between dialog sections |
| lg | 24px | Dialog header/footer horizontal padding, gap between notice and Lite area |
| xl | 32px | Empty-state vertical padding |
| 2xl | 48px | Header height |
| 3xl | 64px | Full-page empty/error state top margin |

Exceptions:

- **Lite area: verbatim.** It uses 2, 6, 10, 12, 14 and 20px values (`gapSm` 6px, `gapLg` 12px, body padding 20px, `--row-height` 36px, page `max-width` 1400px). These are not declared here and must not be edited or snapped to the scale.
- **Page gutter 20px** (`layout.paddingPage`). The header inner container uses `max-width: 1400px; margin: 0 auto; padding: 0 20px` so the product name and controls align with the Lite area's left and right edges.
- **Control height 32px** for header buttons, the workspace select and the user-menu trigger. This is a 4-multiple, but it sits between `lg` and `xl`, so it is an explicit exception. It is not a touch-target claim (this is a desktop-first PMO tool; Lite's own controls are smaller).
- **Lite area wrapper** reproduces Lite's `body` rules: `padding: 20px`, `line-height: 1.4`. See Interaction Contract, "Page structure".

## Typography

Declared for the **SaaS chrome** (3 sizes, 2 weights). Lite-area type is owned by `components.css` and is untouched.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (buttons, inputs, notices, dialog text, menu items) | 14px | 400 | 1.4 (matches Lite `body` and `typography.lineHeight`, so the chrome and the Lite area share one rhythm) |
| Label (form labels, secondary text, dialog meta, workspace switcher label) | 12px | 600 | 1.4 |
| Heading (product name, dialog titles, empty/error state titles) | 18px | 600 | 1.2 |
| Display | not used in chrome | | Lite's 28px/700 `.kpi-value` stays inside the Lite area |

Rules:

- Weights are 400 and 600 only. Buttons use 600 at 14px. Lite's 500 and 700 weights are not used in new chrome.
- Primary button text, dialog titles and the product name are 600. Everything else is 400, except Label (600).
- Sizes 12, 14 and 18 are taken from Lite's own scale (`fontSize12`, `fontSize14`, `fontSize18`), so they exist as Tailwind `text-12`, `text-14`, `text-18` already.
- Existing chrome uses Tailwind defaults (`text-sm`, `text-base`, `text-lg`, `font-medium`). Replace with the mapped sizes above. `font-medium` (500) is removed.

Font loading (within Claude's discretion, recommended): self-host DM Sans (400, 500, 600, 700, woff2) in `packages/tokens` and load it with `@font-face` from the tokens CSS, for both products. The Google Fonts `<link>` in `index.html` is removed. This gives the pinned Playwright image (D-08) identical glyphs for Lite and SaaS without network access, and keeps Lite backend-free.

## Color

All colors come from `packages/tokens` custom properties. The chrome hardcodes no hex values. Two chrome-only tokens are added to every theme block (see below). The Lite area keeps its existing tokens and hardcoded gradients unchanged.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--color-bg-page)` (light `#f4f5f7`) | Page background behind the header and the Lite area |
| Secondary (30%) | `var(--color-bg-white)` (light `#ffffff`), with `var(--color-bg-secondary)` for hover and skeleton fill | Header bar, dialogs, user menu, notices, empty/error cards. Border `var(--color-border)`. Text `var(--color-text-dark)`, secondary text `var(--color-text-light)`. |
| Accent (10%) | `var(--color-accent)` (new, per theme, table below) with `var(--color-on-accent)` for text on it | Reserved list below |
| Destructive | `var(--color-danger)` (new, per theme, table below) with white text | Reserved list below |

Accent reserved for:

1. The fill of the header primary button ("Add project") and the submit button in the project dialogs ("Add project", "Save changes").
2. The `:focus-visible` ring (2px solid, 2px offset) on every chrome control and on the keyboard-reachable Lite controls (`.kpi-card.clickable`, `.risk-summary.clickable`, `.descoped-summary.clickable`, `.zoom-btn`, `.export-btn`, `.filter-toggle`, `.filter-clear`, `.group-control-btn`). The ring only shows on keyboard focus, so it cannot change a parity screenshot.
3. The keyboard-highlighted item in the user menu and in the "Manage projects" dialog list.

Accent is not used for links, headings, icons, borders, hover backgrounds or the theme select. Lite's own accents (`#0065ff` on `.zoom-btn.active`, the theme overrides for `.export-btn` and so on) stay as they are inside the Lite area.

Destructive reserved for:

1. The confirm button in the delete-project dialog ("Delete project").
2. Inline validation and submit error text inside the project dialogs, and the `Retry loading`-adjacent error title in the full-page load error.

`--color-risk` is Lite's at-risk semantic and stays inside the Lite area. The chrome does not use it for destructive actions (the existing `bg-risk` delete button is replaced), because in `blank` and `dark` it is a pastel that fails contrast with white text.

### New tokens (add to `packages/tokens/tokens.css`, one value per theme block)

Contrast is the ratio of white (`#ffffff`) text on the fill, computed per WCAG 2.x. All pass 4.5:1. `--color-on-accent` and the danger button text are `#ffffff` in every theme.

| Theme | `--color-accent` | contrast | `--color-danger` | contrast |
|-------|-----------------|----------|------------------|----------|
| light (`:root`) | `#0065ff` (Lite's `.zoom-btn.active`) | 4.88 | `#c42b0a` | 5.68 |
| dark | `#2563eb` | 5.17 | `#dc2626` | 4.83 |
| professional | `#1d4ed8` | 6.70 | `#b91c1c` | 6.47 |
| colorful | `#4f46e5` | 6.29 | `#dc2626` | 4.83 |
| blank | `#4f46e5` | 6.29 | `#b91c1c` | 6.47 |
| monochrome | `#262626` | 15.13 | `#b91c1c` | 6.47 |
| papallona | `#1e3a5c` | 11.57 | `#b91c1c` | 6.47 |
| evergreen | `#0b3c56` | 11.70 | `#c42a1e` | 5.68 |

Secondary text (`--color-text-light` on `--color-bg-white`) measures 4.52 (light) to 7.81 (monochrome) across all eight themes, so chrome secondary text may use it at 12px and 14px without a per-theme override.

The existing `m3` Tailwind color (teal primary button, focus ring) and the `bg-slate-*` sidebar classes in `AppShell.tsx` are removed. They are not theme-aware.

### Theme set (D-05, D-06, D-07)

Eight themes, in this order and with these labels, identical to Lite's `<select class="filter-select theme-select">`:

`light` Light, `dark` Dark, `professional` Professional, `colorful` Colorful, `blank` Blank, `monochrome` Monochrome, `papallona` Papallona, `evergreen` Evergreen.

All theme blocks live in `packages/tokens`. `roadmap.css` keeps only the `@import`s and Lite's page-level rules. The `.dark` selector aliases in `tokens.css` and the `html.dark` rules in `index.css` and `components.css` (41 `.dark` occurrences in `components.css`, 11 in `index.css`, 2 in `tokens.css`) are rewritten to `[data-theme="dark"]` or deleted. Tailwind `darkMode` changes from `'class'` to `['selector', '[data-theme="dark"]']` so any remaining `dark:` utilities follow the same attribute.

## Interaction Contract

### Page structure (D-02, D-07)

```
<html data-theme="{theme}">
  <header.saas-header>        48px, NOT sticky, scrolls away
  <div.saas-notice>?          one live region (role="status"), only when a notice exists
  <div.lite-area>             reproduces Lite's `body` rules: padding 20px, line-height 1.4,
                              font-family, background var(--color-bg-page), color var(--color-text-dark)
    LiteFilterBar / LiteExportControls / div#roadmap-export / LiteFooter
```

- **The SaaS header is not sticky.** Lite's `.filter-bar` is `position: sticky; top: 10px; z-index: 100`. A sticky SaaS header would cover it or force a different `top`, which breaks parity. The header scrolls away and the Lite filter bar sticks at 10px exactly as in Lite.
- **Preflight.** Tailwind preflight must not restyle the Lite area. Disable `corePlugins.preflight`, add a scoped minimal reset for chrome (`.saas-header`, dialogs, notices), and reproduce Lite's `* { margin: 0; padding: 0; box-sizing: border-box }` reset scoped to `.lite-area *`. The verifiable constraint is that computed styles of every Lite-area element equal Lite's computed styles. The mechanism is the planner's choice (CONTEXT, Claude's Discretion).
- **Visual hierarchy and focal point.** The primary visual anchor of the page is the Lite dashboard KPI row (`.kpi-card` tiles with the 28px/700 `.kpi-value`), which is the first large, high-contrast block below the header. The reading order is: KPI row, then timeline, then the Lite filter bar and export controls. The SaaS header is deliberately subordinate: 48px high, not sticky, neutral `--color-bg-white` surface, 18px/600 product name as its largest type, and `Add project` as the only accent fill in the chrome. No chrome element may use a size above 18px, a weight above 600, or an accent fill other than the primary action, so nothing in the chrome competes with the KPI row.
- **Removed from the app:** the left sidebar, the Dashboard/Timeline/Projects tabs, `FloatingTimelineFilterBar`, `FloatingExportMenu`, `TimelineToolbar`, `ThemeToggle` and the `.filter-bar--timeline-sticky` overrides. Lite's filter bar and export controls are the only versions.
- **Header, left to right:** product name `RoadmapSnap` (Heading), workspace select, flexible space, `Manage projects` (secondary button), `Add project` (primary button), user menu. Below 768px the workspace select wraps to a second row inside the header. Buttons and the select are 32px high.
- **Buttons:** primary = accent fill, white 14px/600 text, 4px radius (`borderRadiusSm`), padding 8px 16px. Secondary = `--color-bg-white` fill, 1px `--color-border`, `--color-text-dark` text. Disabled = 50% opacity, `cursor: not-allowed`. Hover on primary: `filter: brightness(0.92)`. Hover on secondary: `--color-bg-secondary` fill. No transitions beyond Lite's `0.2s ease`.

### State owned by the SaaS page

Mirrors Lite's `AppState` fields: `filter {status, riskOnly, descopedOnly, search}`, `sort {by, order}`, `zoom` (`3mo`/`6mo`/`12mo`/`all`, default `all`), `showGantt`, collapsed groups, `activeDependencyGraph`, `theme`. A React state change re-renders the whole Lite area (the equivalent of `renderRoadmap()`); no imperative DOM patching.

- None of this is persisted except `theme`. Reloading resets filters, sort, zoom and collapsed groups, as in Lite.
- **Switching workspace resets** filter, sort, zoom, collapsed groups and `activeDependencyGraph` to defaults (Lite's `AppState.reset()`). The theme is kept.
- Any change to filter, sort or zoom closes an open dependency graph (Lite calls `closeDependencyGraph()`), except toggling `showGantt`.

### Filters, zoom, dependencies (VIEW-03, VIEW-04)

- Search is debounced 150 ms. After the re-render the search input regains focus with the caret at the end of the text, as Lite does. In React this means the input keeps its identity across renders.
- A click outside `.kpi-card.clickable`, `.risk-summary.clickable`, `.descoped-summary.clickable`, `.filter-bar`, `.export-controls`, `.info-link` and `.data-source-row` clears the status, risk and descoped filters (`clearStatusFilterOnOutsideClick`). A click outside the dependency graph closes it. Both document-level listeners are registered once on mount and removed on unmount.
- Status, risk-only and descoped-only are mutually coordinated exactly as in `filterByStatus`, `toggleRiskFilter` and `toggleDescopedFilter` (selecting one clears the others). This logic comes from the core `filterDeliverables` and the pure filter-state helpers, not from a re-implementation.
- Dependency arrows are drawn after the DOM commits (`useLayoutEffect`) and redrawn when the graph is active, risk-only is on, zoom or sort changes, or the window resizes. They are cleared when none of those apply. Tooltips and blocking detection use core output.

### Theme (D-06, D-07)

- The only theme control is the Lite `Theme:` select inside the Lite filter bar. The header has no second theme control.
- **Before first paint:** a blocking inline script in `packages/app/index.html` reads `localStorage['roadmapsnap-theme']`, maps legacy `dsm-firmenich` to `evergreen`, accepts only the eight valid values (anything else becomes `light`), and sets `data-theme` on `<html>`. After the user record loads, a `users.preferences.theme` value that differs from the cache replaces it (and updates the cache). A first-time user with no cache and no preference gets `light`.
- **On change:** set `data-theme`, write the cache, then `PATCH /auth/me` with `{ preferences: { theme } }`. The change is optimistic. If the PATCH fails, keep the applied theme, do not roll back, and show the "theme could not be saved" notice. The notice stays for 6 seconds or until dismissed.
- **API dependency:** `packages/api/src/routes/auth.js` currently accepts only `light` and `dark` (schema enum at line 31, the guard at line 55) and `UserPreferences['theme']` is a two-value union. Both must accept all eight values or every non-light/dark selection is silently reset to `light`. See Planner Notes, item 2.

### Export (VIEW-06, D-12)

- The five buttons keep Lite's behavior: PNG targets ids `roadmap-export`, `summary-section`, `timeline-section` with the names `Full-Roadmap`, `Summary-Dashboard`, `Timeline-Only`. CSV and JSON download the core builders' output, byte-identical to Lite.
- PNG uses `html2canvas` on the Lite area with Lite's options. The canvas background is the resolved `--color-bg-page` of the active theme (never transparent or a white fallback), so every theme exports with its own page color.
- While a PNG capture is running the PNG buttons are `disabled` with `aria-busy="true"` and their labels are unchanged (no visual diff). On failure, `console.error` as Lite does, plus the "PNG export failed" notice.

### Dialogs (D-03)

- Native `<dialog>` with `showModal()` (existing pattern). Escape and a backdrop click close it. Focus is trapped by the platform and returns to the trigger on close. The first focusable element receives focus, except in the delete dialog, where `Keep project` does.
- Dialog surface: `--color-bg-white`, 1px `--color-border`, 8px radius (`borderRadiusLg`), `shadow-xl`, backdrop `rgba(0,0,0,0.4)`. Widths: projects dialog `max-w-2xl`, form dialog `max-w-lg`, delete dialog `max-w-sm`. The projects dialog body scrolls at `max-height: 70vh` while its header stays fixed.
- Opening Add project or Manage projects never changes Lite-area state. After a create, edit or delete succeeds, the dialog closes and the roadmap refetches. No toast, because the Lite area updating is the confirmation.
- Viewers do not see `Add project` and the projects dialog hides `Edit` and `Delete` (via `useRole`). The API remains the enforcement point. Full read-only UI is EDIT-08, Phase 3.

### Loading

- While workspaces or projects load, render a skeleton of three blocks with fixed heights (56px filter-bar, 240px dashboard, 320px timeline) in `--color-bg-secondary` with a 1.5 s opacity pulse. Fixed heights avoid layout shift when the Lite area mounts. Under `prefers-reduced-motion: reduce` the pulse is disabled.
- The header renders immediately with the workspace select disabled until workspaces arrive.

### Accessibility additions that do not change markup parity

The golden-markup test compares tag tree and class lists. These additions are allowed because they are attributes, not structure or classes:

- Clickable `div`s that Lite wires with `onclick` (`.kpi-card.clickable`, `.risk-summary.clickable`, `.descoped-summary.clickable`) get `role="button"`, `tabindex="0"` and Enter/Space activation in the SaaS render only.
- Selects and inputs in the Lite filter bar keep Lite's existing labelling. Add `aria-label` where there is no visible label (`Search by name`, `Sort by`, `Sort order`).
- The notice region is `role="status"` `aria-live="polite"`. Error blocks use `role="alert"`.
- Focus-visible rule from the Accent list, shared through `packages/tokens/components.css`.
